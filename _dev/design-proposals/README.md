## F 案「緑青（ろくしょう）」（2026-11-13 に追加）

A+ 案を全ツールに入れたあとで、「判断を任せるので作り直してみてほしい」という依頼から、色や枠の足し引きではなく一から組み直した案です。A+ 案（決定済みで、各ツールの PR に入っているもの）と並べて比べるために置いています。見比べた結果、**F 案に決まりました**（2026-11-13）。

元にしたのは、切り替えボタンが入ったあとの置き場サイトとチャットウィンドウメーカー（v1.13）で、変えたのは `<style>` の中だけです。明るさは画面右上の「自動 / ダーク / ライト」で切り替えます（`?theme=` は使いません）。

### 考え方

- **夜の卓と、キャラクターシート**: ダークは墨色の地（`#10141a`）に紙色の文字（`#e9e6df`）。ライトは紙（`#f3f0e9`）に墨の文字。同じ道具を、夜の卓の上と、昼の紙の上に置いたように見せます。
- **差し色は緑青 1 色**（ダーク `#5ccfc0`、ライト `#0e6a5c`）。A+ 案の琥珀は、このツールの警告の橙（「ルームの URL をそのまま OBS に入れると…」など）とほぼ同じ色合いで、注意書きが見出しや差し色に紛れていました。緑青にしたので、橙は警告だけの色になります。プレビューの成功（青）・失敗（赤）とも重なりません。
- **見出しは罫線の上に置く**: 設定のまとまり（`fieldset`）は、キャラクターシートの区切りのように「◆ 見出し ———」の形です。HTML の `legend` が枠線に割り込む、ブラウザ本来の描き方をそのまま使っています（A+ 案の `float` の工夫が要りません）。同じ形を、使い方の見出しと置き場サイトの見出しにも使っています。
- **部品の形を揃える**: 入力欄・プルダウン・ボタン・色の欄は、同じ高さ（28px）、同じ縁の色、同じ角（4px）。プルダウンの矢印は自前で描き、色の欄は中の色が縁いっぱいに見えるようにしました。スライダーとチェックボックスはブラウザの部品のまま差し色だけ変えています（塗られた長さが見える、という元の良さを残すため）。
- **枠は、まとまりと操作できる部品にだけ**: 設定のパネル、プレビュー、その下の箱、保存・コピーの行。縁の色は地に対して 3:1 以上あります。A+ 案で好評だった「枠があると見やすい」は残しつつ、パネルの中は罫線と余白で区切って、箱の中の箱を減らしました。
- **プレビューには飾りを足さない**: A+ 案の黒い縁と四隅の印はやめました。作っているデザインの一部に見えてしまうためです（A+ 案でも、前景フレームメーカーなど 3 つのツールでは外していました）。
- **文字は 13px**: A+ 案の 12.5px より少しだけ大きくし、行の間も 6px から 8px にしています。1 画面に入る設定は 1〜2 行ぶん減りますが、Windows の Yu Gothic UI で小さすぎないことを優先しました。
- **置き場サイト**: ツールは、絵を左に置いたカードを 2 列に並べます。A+ 案の 1 列の表より、9 つのツールを見渡すための縦の長さが短くなります。「こんなときに」は緑青の小さな見出しにして、探している人の目が最初に届くようにしました。

### A+ 案と比べて

- A+ 案のほうがよい点: 行が詰まっていて 1 画面に入る設定が多い。琥珀は暖かく、暗い部屋で目に優しい。すでに全ツールの PR ができている。
- F 案のほうがよい点: 差し色と警告の色が分かれる。部品の形が揃っていて、ブラウザの素の部品に色を塗っただけに見えない。プレビューに飾りがない。ライトで差し色を別の色に言い換えなくてよい（A+ 案はライトで琥珀の文字を茶色に替えています）。
- F 案にする場合の手間: スタイルの共通部分を入れ替え、各ツールの「This tool only」の段落を F 案の変数（`--raised` など）に合わせて書き直します。切り替えボタン・辞書・HTML はそのまま使えます。

## 見方

ファイルを直接ダブルクリックで開くと、ブラウザによっては iframe のプレビューや言語ファイルが動かないので、静的サーバーで開いてください。

```bash
cd _dev/design-proposals
python -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開くと、入口のページから各画面へ行けます。英語・韓国語は `?lang=en` `?lang=ko` を付けるか、各画面の右上で切り替えます。

A 案と C 案にはダークとライトがあります。ふだんは OS の設定（ダークモード・ライトモード）に合わせて自動で切り替わります。URL に `?theme=light` `?theme=dark` を付けると OS に関係なく選べます（`?lang=en&theme=light` のように並べても使えます。言語を切り替えても `theme` は残ります）。

- 3 案のチャットウィンドウメーカーは、同じサーバーで開くとブラウザの自動保存を共有します。1 つの案でひな形や色を変えてから別の案を開けば、同じ設定のまま見た目だけを比べられます。
- 置き場サイトのツールのリンクは、公開中の本物のツールに飛びます（HTML は変えていないため）。
- 元に戻したいときは、各フォルダを消すだけです。ほかのファイルには触れていません。

## 作り方（何を変えて、何を変えていないか）

- 変えたのは、各 `index.html` の `<style>` の中だけです。例外として、A 案と C 案には `?theme=` を読む 1 行の `<script>` を `<head>` に足しました（見比べるためだけのもの。下の「ダークとライト」を参照）。HTML の並び、文言、`data-*` 属性、`id`・クラス名、`role` は 1 文字も変えていません。JS（`app.v1.js` `css.v1.js` `mock.v1.js` など）と辞書（`lang.*.v1.js`）も元のままのコピーです。
- このため、ひな形の適用・タブ・コピー・プレビュー・翻訳は元と同じに動き、**書き出す CSS も元と 1 バイトも変わりません**（確かめ方は下に）。
- チャットウィンドウメーカーのコピー元は shiki365/chat-window-maker の `964cffc`（2026-10-30、v1.12）です。`ogp.png` と `README.md` はコピーしていません（OGP は絶対 URL で公開中のものを指しているため）。ライセンスは MIT（Copyright (c) 2026 shiki365）で、`LICENSE` も一緒に置いています。

## 3 つの案

### A 案　計器盤（暗い・密度高め）

- **狙い**: 画像編集ソフトや DAW の「インスペクター」のような、仕事の道具の画面。カードの箱をやめ、細い線と見出しの帯で区切ります。行を詰め（行間 6px、ラベル 100px）、1 画面に見える設定を増やしました。設定を何度も行き来して詰める人に向けた案です。
- **色**: 地 `#111214`、面 `#17181b`、線 `#2c2e33`。差し色は琥珀 `#e3a63b` の 1 色だけ（選んだタブの上の線、見出し、スライダー、主ボタン）。主ボタンは琥珀に黒文字。紫をやめ、暖かい暗色で「卓の灯り」の雰囲気にしました。
- **文字**: 本文 12.5px。数値・版・言語の切り替え・「OBS 31〜」の札は等幅（`Consolas, "BIZ UDGothic"`）。置き場サイトは見出しに `01` `02` の番号。
- **面と線**: 角はほぼ直角（2px）。影なし。置き場サイトのツールは表の行のように並べ、仕様（作れるもの・使う場所）を右の列に寄せました。
- **プレビュー**: 右の列いっぱいに広げ、下の操作をすべて帯（ツールバー）として積みます。保存・コピーの行だけ地の色を変えて、作業の終わりが分かるようにしています。

### B 案　紙と墨（明るい・ゆったり）

- **狙い**: 生成りの紙に墨の文字、朱の差し色。見出しはシステムの明朝体（`"Yu Mincho", "Hiragino Mincho ProN"` など）で、TRPG のルールブックやシナリオ集のような手触りにしました。説明文の多いツールを「読み物」として読ませる案です。
- **ライトにした理由**:
  1. このツールで時間がかかるのは、配信中ではなく**準備のとき**です。明るい部屋で説明文（OBS の手順、うまく映らないとき）を読み込む場面が多く、長い日本語は明るい地のほうが読みやすいためです。
  2. ただし、**プレビューだけは暗い台紙（`#2a2824`、12px の縁）に載せています**。チャットウィンドウは暗い窓が多く、白い地の横に置くと実際より沈んで見えるので、OBS の映りの判断は台紙の中の「色つき・市松・暗い・明るい」の背景で行えるようにしました。
  3. 真っ白（#fff）は避け、紙の色 `#f3efe5` にしてまぶしさを抑えています。
  4. 夜に長く使う人のために、全ツールへ広げるときは `prefers-color-scheme: dark` で暗い版（「墨」）を足す余地があります。色はすべて変数にしてあるので、`:root` の値を差し替えるだけで作れます（今回は未作成）。
- **色**: 地 `#f3efe5`、面 `#fbf9f3`、線 `#cfc6b3`、文字 `#23201b`、補足の文字 `#635c50`。差し色は朱 `#b23a24`、主ボタン `#ad3722` に白文字。
- **文字**: 本文 13.5px、行間広め。設定の見出しは明朝 16px と朱の小さな四角。タブは索引のように下線で選択を示します。
- **面と線**: 罫線（区切りの 1px、ヘッダーとフッターの二重線）で組み、箱は最小限。置き場サイトのツールは「第一」「第二」…の番号を罫線の端に付けた 2 列の誌面組み。英語・韓国語では番号を数字、FAQ の「問」を「Q」に替えています。

### C 案　オンエア（暗い・太い線・大きな文字）

- **狙い**: 配信卓・放送用モニターの雰囲気。太い 2px の枠、直角、大きく太い見出し、赤い丸（タリーランプ）。押す場所を大きくし（入力欄 32px）、迷わず操作できるようにした案です。
- **色**: 地 `#0c0e11`、面 `#15181d`、枠 `#4a525e`。差し色は黄緑 `#c6ee3a`（「選んでいる・進む」の意味だけに使う）で、選んだタブと主ボタンはベタ塗りに黒文字。赤 `#ff4f45` は見出しの丸だけ。
- **文字**: 本文 13.5px、ラベルと見出しは太字。`font-feature-settings: "palt"` で和文を詰め気味に。スライダーの値は小さな表示窓に入れます。
- **面と線**: 光る影の代わりに、黒いずらし影（`6px 6px 0 #000`）を置き場サイトのカードと主ボタンだけに。押すと沈みます（`prefers-reduced-motion` では沈みません）。
- **プレビュー**: モニターに見立て、黒い縁と四隅のセーフエリアの印（`.stage::after`、操作の邪魔をしない `pointer-events: none`）。保存・コピーの行は白い帯にして、最後の操作をいちばん目立たせています。

## ダークとライト（A 案・C 案）

### 仕組み

- 色はすべて `:root` の変数で持ち、ライトでは変数の値だけを差し替えます。部品ごとの指定は 1 つで、ダークとライトで同じです。
- 切り替えは CSS の `@media (prefers-color-scheme: light)` です。OS がライトモードならライトになります。JS も辞書も使いません。
- 見比べ用に、`<head>` の 1 行の `<script>` が `?theme=light|dark` を読んで `<html data-theme="…">` を付けます。`:root[data-theme=light]` と、`data-theme=dark` のときに OS のライトを打ち消す `:root:not([data-theme=dark])` で効きます。
  - 本番に入れるときは、この 1 行を消せば「OS に合わせるだけ」になります。画面の中に切り替えボタンを置くなら、そのとき `data-theme` を付けて `localStorage` に覚えさせ、ボタンの文言を `lang.*.v1.js` に足します。
- 元の CSS に直書きされていた色（見出しの帯、札、危ないボタン、フォント一覧のダイアログの選択色、C 案の縞模様やずらし影など）は、`--strip` `--tag-fg` `--danger-bg` `--pick` `--stripe` `--hard` などの変数に置き換えました。各 `<style>` の最後の「Theme」の段落にまとまっています。
- プレビューの中身と 4 種の背景、プレビュー下の「表示 100%」の注記はどちらのテーマでも同じです。

### A 案のライト

- 地 `#f4f4f1`、面 `#ffffff`、線 `#d3d1ca`、文字 `#1d1c19`、補足の文字 `#5d5b54`。
- 琥珀は白地では文字色として薄すぎる（3:1 未満）ので、**文字や線として使う差し色は茶 `#8a5000`** に替えました。**ボタンは琥珀 `#e3a63b` に黒文字のまま**なので、ダークと同じ「琥珀を押す」感じが残ります。
- 線で区切って面の色が少ない作りなので、ほぼ変数の差し替えだけで成り立ちます。

### C 案のライト

- 地 `#f1f2f4`、面 `#ffffff`、文字 `#0c0e11`、補足の文字 `#4a5260`。2px の枠は黒 `#14171c` にして、印刷した進行表（キューシート）のような見た目にしました。
- 黄緑 `#c6ee3a` は白地では文字にもボタンの地にも使えない（1.2:1 程度）ので、**選んだタブと主ボタンは「黒の地に黄緑の文字」**に反転しました。黄緑は「選んでいる・進む」の合図として残ります。文字や線として使う差し色は深緑 `#3f6f00`。
- セーフエリアの四隅の印と、保存・コピーの帯の「CSS をコピー」は、どちらのテーマでも黄緑のままです（暗いプレビューや黒い帯の上にあるため）。
- 黒いずらし影は残しましたが、白地では強めに見えます。好みが分かれるところなので、見比べて決めてください。

## A+ 案（A に枠を足した版）

A 案を見て「枠があったほうが見やすい」と感じたことから、A の色・詰まり具合・ダークとライトはそのままに、C 案の「まとまりを枠で囲む」考え方だけを足した版です。枠の太さ違いで 2 つ作りました（`a-frame-1px/` と `a-frame-2px/`）。違いは枠の太さだけです。

- **囲むもの**: 設定のパネル全体、プレビュー下の「メッセージを送って確かめる」「OBS のブラウザソースに入れる URL」、保存・コピーの行、置き場サイトの各ツール・目次・使い方・FAQ・連絡先。A では線を積み重ねる帯だったプレビューの右の列を、すき間をあけた別々の箱にしました。
- **入力欄とボタン**: 縁を同じ枠の色にしました。マウスを乗せると縁が文字の色に変わります。
- **プレビュー**: 黒い縁（ライトでは墨色）と、琥珀の四隅の印でモニター風にしました。印は操作の邪魔をしません（`pointer-events: none`）。
- **足していないもの**: C 案の太い見出し、黒いずらし影、黄緑。A の落ち着きは崩していません。
- **枠の色**: ダーク `#6a6d75`、ライト `#8a887f`。どちらも地に対して 3:1 以上あり、操作できる部品の縁として見分けられる濃さです（WCAG 1.4.11）。
- **仕組み**: A 案の `<style>` の後ろに「Frames」の段落を足しています。太さは `:root` の `--fw`（1px / 2px）、色は `--frame` と `--bezel` の変数で持っています。本番では、決めた太さを `--fw` に入れれば済みます。

| コントラスト | 文字（ボタン・入力欄・値の表示を含む）は背景に対して 4.5:1 以上。差し色を背景にするボタンは、明るい差し色なら黒文字、暗い差し色なら白文字 |
| 色の持ち方 | `:root` の変数で持つ。元からある `--bg --panel --line --line-soft --fg --muted --accent --button` に加え、`--link --button-fg --button-hover --field --control --control-line --control-hover --warn --error` を足した（案によって一部） |
| フォーカス | `:focus-visible` で差し色の 2〜3px の outline。タブの帯の中は内側に描く |
| 動き | 色の切り替えの transition は `prefers-reduced-motion: no-preference` の中だけ。C 案の押し込みも reduced-motion では止める |
| 幅 375px | 横にはみ出さない。グリッドの列は `minmax(0, 1fr)`、タブの帯は `overflow-x: auto`（元のまま）。860px 以下で設定とプレビューを縦に並べる（元のまま） |
| 言語 | 英語・韓国語の長い文言でも列が広がらないよう、固定幅の列を増やさない。B 案の漢数字など日本語向けの飾りは `:lang(ja)` 以外で差し替える |

## 全ツールへ広げるときに直す場所と注意点

各ツールの `index.html` の `<style>` を、選んだ案のもの（`a-frame-1px/chat-window/index.html` の `<style>`）に置き換えるのが基本です。チャットウィンドウメーカーと同じ骨組み（`.panel` `.tabbar` `fieldset` `.row` `.with-value` `.color-alpha` `.stage-wrap` `.stage` `.bar` `.seg` `.tester` `.note` `footer`）を使っているツールは、ほぼそのまま移せます。

1. **`:root` の色**: 案の変数をそのまま使う。ツールにだけある色（成否の色、警告の橙など）は、新しい地の上で 4.5:1 を測り直す。B 案（ライト）では、暗い地を前提にした `#ffb86b` のような明るい警告色が読めなくなるので `--warn` に置き換える。
2. **直書きの色を変数にする**: 元の CSS には `#14151b`（入力欄）、`#2f3140` `#3a3d4f` `#464a5e`（ボタン）、`#a8abff`（リンク）、`#5a2f36`（危ないボタン）などが直書きされている。案ではこれを `--field` `--control` `--link` などに置き換えた。ほかのツールも同じ置き換えが必要。
3. **ツールごとの部品**: 前景フレームメーカー・場面転換素材メーカーなど、キャンバスや書き出しの一覧があるツールは、その部品のクラスに案の線と角の決まりを当てる。プレビューの背景（市松・暗い・明るいなど）とプレビューの中身は変えない。
4. **JS が足すスタイル**: `pcfonts.v2.js` のフォント一覧のダイアログは、自分で `<style>` を足し、ページの変数（`--panel` `--fg` `--line` など）を読む。マウスを乗せたときの色だけ直書き（`#2a2c38`）なので、各案では `body .pcf-list …` で上書きしている。ほかの JS が足すダイアログや通知（`i18n.v1.js` の `.lang-feedback` など）も同じように確かめる。
5. **iframe の `color-scheme`**: プレビューの iframe には `color-scheme: normal` を残すこと。消すと Chromium が iframe を白く塗る。B 案（ライト）では `:root` が `color-scheme: light` になるが、iframe 側の指定はそのまま。
6. **HTML の構造に頼る指定**: A 案は `legend` を `float` にして見出しの帯にしている（`legend + * { clear: both; }` とセット）。3 案とも「保存・コピーの行」を `.source-url + .bar` で選んでいる。HTML の並びが違うツールでは、この隣接の指定が当たらないので、ツールごとに選び方を変える。
7. **タブの帯**: 案によっては 5 個のタブが 1 行にぎりぎり収まる幅にしている。タブが 6 個以上あるツールや英語では、`overflow-x: auto` で横にスクロールする（元と同じ動き）。
8. **ダークとライト**: 両方を持つなら、新しく足す色は必ず変数にして、ライトの値も同時に決める。直書きの色が 1 つ残ると、片方のテーマだけで読めなくなる（C 案のライトでも、保存の帯のファイル名欄で一度起きた）。
9. **確かめ方**: 下の「確かめたこと」と同じく、3 言語 × 1280 / 375px（ダークとライトの両方）でコンソールのエラー、横のはみ出し、コントラストを測り、書き出す CSS（や画像）が元と同じかを比べる。

## 確かめたこと

ヘッドレスの Chromium（Playwright）で確かめました。

- **3 案 × 2 画面 × 幅 1280 / 375 × 日本語・英語・韓国語（36 通り）**: コンソールのエラー 0、横のはみ出し 0、コントラスト 4.5:1 未満の文字 0。チャットウィンドウメーカーは 5 つのタブをすべて開き、`<details>` も開いた状態で測りました。
  - コントラストは、見えている文字を含む要素（ボタン・入力欄・値の表示を含む）ごとに、文字色と、親をたどって重ねた背景色から計算しています。背景が画像やグラデーションの上にある文字（プレビューの「表示 100%」の注記、C 案の置き場サイトの見出しの縞模様の上）は機械では測れないので除外しました。どれも黒い帯か、ほぼ地の色の上です。
- **チャットウィンドウメーカーの動き（元のツールと 3 案で同じ手順）**:
  - 書き出す CSS: 最初の状態、ルームの URL を入れてから 11 種のひな形を順に適用したそれぞれ、スライダーを動かしたあとの合計 13 の状態で、元と**完全に同じ文字列**（3 案とも）。
  - プレビュー: スライダーを動かすと、iframe の CSS が書き出す CSS と同じものに更新される。「ダイス：成功」を送るとメッセージが 1 件増える。
  - タブ: 右矢印で次のタブへ、End で最後、最後から右矢印で最初に戻る。フォーカスの outline が出る。
  - コピー: 「CSS をコピー」でクリップボードの中身が書き出す CSS と一致し、案内の文が出る。ルームの URL から `/chat` の URL が作られ、上の欄に出る。
  - HTML の `<style>` 以外の部分と JS・辞書・LICENSE が元と同じこと（バイト単位の比較）。A・C 案は、足した `?theme=` の 1 行を除いて同じです。
- **F 案**: 「OS がダーク」「OS がライト」「ライトを選んだ」「ダークを選んだ」の 4 通り × 2 画面 × 幅 1280 / 375 × 3 言語で、エラー・はみ出し・4.5:1 未満の文字はどれも 0 でした（チャットウィンドウメーカーは全タブを開いた状態）。切り替えボタンは 13 項目の確認をすべて通りました。チャットウィンドウメーカーの書き出す CSS は、ダークでもライトでも v1.12 と完全に同じです（66 の状態: ひな形 11 種、スライダー 23 本、チェックボックスとプルダウン 32 個など）。縁の色が地・面・入力欄のどれに対しても 3:1 以上あることは、計算で確かめました。
- **A+ 案（枠 1px・2px）**: ダーク・OS のライト・`?theme=light` の 3 通りで、2 画面 × 2 幅 × 3 言語を測り、エラー・はみ出し・4.5:1 未満の文字はどれも 0 でした。書き出す CSS（13 の状態）と、タブ・コピー・プレビューの動きも、ダークとライトの両方で元と同じでした。
- **A・C 案のライト**: 上と同じ 2 画面 × 2 幅 × 3 言語を、次の 3 通りで測りました。どれもエラー・はみ出し・4.5:1 未満の文字が 0 です。
  - OS がライト（ブラウザの `prefers-color-scheme: light`）
  - OS がダークで `?theme=light`
  - OS がライトで `?theme=dark`（ダークに戻ること）
  - OS がライトのときも、書き出す CSS（13 の状態）とタブ・コピー・プレビューの動きが元と同じことを確かめました。

## 確かめていないこと

- Windows の実際のフォント（Yu Gothic UI・Yu Mincho）での見え方。確かめた環境は Linux で、別のフォントで表示されています。特に B 案の明朝体の見出しは、Windows では細く見える可能性があります。
- Safari・Firefox での表示、実機のスマホでの操作（タッチでのスライダー操作など）。
- スライダーのドラッグ中に周りの行が出入りしないこと（JS を変えていないので元と同じはずですが、ドラッグ操作そのものは試していません）。
- PC のフォント一覧のダイアログ（`queryLocalFonts` の許可が要るため、ヘッドレスでは開いていません）。
- OBS の中での表示（このツールのページ自体は OBS に入れないので、書き出す CSS が同じなら影響はありません）。
