# 説明動画のキット（`_dev/motion`）

ツールの告知・紹介に使う「説明動画」を作るための部品。**画面録画ではなく**、簡略化したツールの画面をカーソルが操作していく動画を、HTML で描いて 1 コマずつ撮る。シーンメーカーの告知動画（2026-11-22）を作ったときに、ほかのツールでも使えるように分けた。

| ファイル | 中身 |
| --- | --- |
| `kit.js` | 部品（`window.Motion`）。動画のページが `<script src>` で読む |
| `render.js` | ヘッドレス Edge で 1 コマずつ撮って mp4 にする（Node 22 以上） |
| `example.html` | いちばん小さい見本。新しい動画はこれをコピーして始める |

実際の動画の例: シーンメーカーの `kokofolia-scenes/media/recorder/motion/explainer.html`（22 秒、`media/` は公開しないので手元だけ）。

## なぜこの作り方か

- 画面録画は文字が小さく、スマホの X ではほとんど読めない。簡略化した画面なら、カメラで寄って見せたい所だけ大きくできる
- **操作している感じ**（カーソルが動く・ドラッグする・押すと反応する）があると、何をするツールか分かりやすい（本人、2026-11-22）
- どの時刻でも最初から描ける作り（`render(t)`）なので、コマ落ちなく撮れ、ブラウザで好きな所から確かめられる

## 決まり（X の数字と本人の意見から。数字は Obsidian の「X の投稿の反応（ツール公開）」）

- **長さは 15〜22 秒**。いちばん伝えたいこと（何ができるか）を最初の 3 秒に。10 秒前後で見る人が大きく減る
- **最初のコマがサムネイル**。最初のコマから、左上のチップ（ツール名）と字幕（できること）が出ている（`a: 0` の字幕は最初のコマで出ている）
- **字幕は上の帯に 1 つずつ**。本文 76px で 18 字まで、補足 44px。1 つの字幕に言いたいことは 1 つ。2.5 秒以上出す
- **ほかのサービス（ココフォリアなど）を下げる比較はしない**（本人、2026-11-22。「ココフォリアだけだと × 20 回」のような比較もやめた）
- **見せる操作は、ツールで本当にできることだけ**。ココフォリア側の動き（ZIP を盤面にドロップすると読み込める、など）も、ツールの説明や本体で確かめてから描く
- ココフォリアの画面は似せすぎない簡略化にし、左上に「ココフォリア」と書く。終わりのカードに「非公式」
- **音は付けない**（X は無音で自動再生）。本番は **60 fps**（カーソルがなめらか）
- **終わりのカード**: ツール名、ひとこと、要点 3 つ、URL、「無料・登録不要｜非公式」
- 窓の上の帯（書き出しボタンなど）が字幕の後ろに来ないように、カメラの高さを決める。字幕の陰（`shade`）は上から 146px までは完全に隠れ、262px で消える

## 作り方

1. ツールのリポジトリの `media/recorder/motion/` に HTML を 1 枚作る（`example.html` をコピー）。`kit.js` は相対パスで読む（例: `../../../../shiki365.github.io/_dev/motion/kit.js`）
2. 絵コンテを時刻で書く: 場面ごとに「字幕・カメラ・カーソルの動き・画面の反応」。時刻は `T` のように 1 か所にまとめると、あとでずらしやすい
3. ブラウザで開いて確かめる（スペース: 再生／停止、矢印: 1 コマ、`?t=8` で 8 秒から）。手元のサーバー（`claude-work-static`、8765）でも、ファイルを直接開いてもよい
4. 静止画で確かめる: `node _dev/motion/render.js <page.html> --stills 0,3.5,8 --out x.mp4` → `x-stills/` に PNG
5. 30 fps で通して撮り、`--sheet` の 1 秒ごとの一覧（左から右、上から下）で流れを確かめる
6. 60 fps で本番: `--fps 60 --sheet`。崩れたコマが無いかは、各ツールの `media/recorder/fix-glitch.py` などで確かめる

## 部品（`window.Motion`）

| 名前 | 使い方 |
| --- | --- |
| `k(t, a, b)` | t が a〜b のどこか（0〜1） |
| `ease.out` / `inOut` / `in` / `soft` / `back` | 動きの緩急（`back` は少し行き過ぎて戻る。ポンと出るとき） |
| `span(t, a, b, c, d)` | a〜b で出て、c〜d で消える（0→1→0） |
| `track([[t, 値, 緩急]…])` | 時刻ごとの値（数か数の配列）をつなぐ |
| `el(親, class, html, 幅, 高さ)` | 絶対配置の要素。親を省くと舞台 |
| `put(要素, x, y, 倍率, 不透明度, 角度)` | 左上を (x, y) に。倍率と角度は中心まわり（`.m-abs.tl` を付けると左上まわり） |
| `layer()` | 舞台と同じ大きさの入れ物（カメラで動かす「世界」や、上に重ねる層） |
| `camera(世界, [[t, x, y, 倍率]…])` | 世界の点 (x, y) を字幕の下の真ん中に、その倍率で。`toScreen(t, x, y)` で舞台の位置 |
| `cursor(層, { start, moves, clicks, holds })` | カーソル。`moves: [{ a, b, to }]`、`to` は位置か `t => 位置`（カメラが動いても指した物から外れない）。`holds` は押したまま（ドラッグ）。押すと波紋 |
| `captions(親, [{ a, b, main, sub }])` | 上の帯の字幕。`<b>` で強調色 |
| `shade()` / `chip(親, html)` | 字幕の後ろの陰 / 左上のツール名 |
| `typed(文, t, 始め, 速さ)` / `caret(t)` | 打っている途中の文字 / 点滅するカーソル |
| `endCard(親, { title, tagline, points, url, note })` | 終わりのカード。`(t, 出す時刻)` で描く |
| `setup({ duration, render })` | 最後に 1 回。`render.js` はこれを待つ |

## 技術メモ

- `render(t)` は**状態を持たない**: 毎回その時刻の位置・不透明度・文字を決め直す。前のコマに頼らない
- 要素は**最初に全部作る**。重なりは作った順（後から作ったものが上）。下の層から: 世界 → 上に重ねる層（運ぶ物・カーソル）→ 陰 → 字幕 → チップ → 終わりのカード
- 画像は canvas で描いて data URL にする（外から読まない。撮るたびに同じ絵になる）
- ページの `<style>` より `kit.js` の CSS が後から入るので、`.m-abs` と同じ詳しさの指定は kit に負ける。上書きするときは `.m-abs.tl` のように詳しくする
- カメラ: 世界の層に `translate` と `scale`。運ぶ物（ドラッグ中のファイル）は上の層で、大きさにカメラの倍率を掛けると画面の部品と大きさがそろう
- ヘッドレス Edge はまれに崩れた画面（半分の大きさで 2 × 2）を返すので、`render.js` は 1 コマを 2 回撮って比べる
- フォントは Yu Gothic UI（Windows 標準）。URL などは Consolas
- 撮る速さ（この PC）: 30 fps・660 コマで約 80 秒、60 fps・1,320 コマで約 160 秒
